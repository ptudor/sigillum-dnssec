## New defects introduced by the fixes (follow-up worklist, ranked)

These were found by re-checking the changed code, as the verification task required. All are new (or newly load-bearing) relative to the pre-fix tree.

1. **`unwindAdd` can delete a surviving orphan key half** (from R-028's new refusal path). `runAdd` computes `kskGenerated`/`zskGenerated` as `!fileExists(<domain>.<type>.key)` (`main.go:811-812`); with a `.private`-only orphan the flag is true, `recoverOrGenerateKeys` returns the R-028 orphan-refusal error, and `unwindAdd` (`main.go:819` → `main.go:411-427`) **deletes the surviving `.private`** — the only recoverable copy of a key whose DS may be live at the parent. Violates the finding's own "surviving half stays on disk" criterion and the never-delete-keys policy, on the `add` path only (daemon and `SignAll` paths are safe). Fix: base the `*Generated` flags on *both* halves being absent, or skip key deletion when the error is the orphan refusal.
2. **Wildcard-synthesized positive answers now read `bogus`** (validator, from R-082's fold-in). The pre-existing branch at `internal/validator/validator.go:566` routes any RCODE-0, CNAME-free response containing NSEC/NSEC3 into the NODATA denial path without checking the answer section is empty. RFC-compliant wildcard-expanded answers carry NSEC/NSEC3 (the no-closer-match proof), so they misroute, the denial proof fails, and — now that R-082 folds `RecordValidation` into the verdict — the overall result is a false `bogus` for any name synthesized by a wildcard in a signed zone. Pre-fix the same misroute was cosmetic. Fix: only treat a response as NODATA when the answer section holds no records of the queried type; route wildcard-positive answers through `verifyWildcard`.
3. **Descendants of unsigned zones read `indeterminate` instead of `insecure`** (validator, from R-081). The `len(parentDNSKEY)==0` "parent not secured → insecure" branch (`validator.go:1207-1212`) is effectively unreachable below the root: `validateWithCache` never clears `parentDNSKEY` when a zone is insecure (`validator.go:262-264`), so for a zone cut under an unsigned zone the DS-absence proof is demanded from a parent that cannot produce one and the zone reads `indeterminate` ("possible downgrade attack"). Contradicts the FIXES entry's own claim. Fails closed, but misclassifies a common legitimate state. Fix: clear (or flag) `parentDNSKEY` when the parent resolves insecure, so the insecure-ancestor branch is reachable.
4. **ZSK rollover can stall indefinitely on frequently-edited zones** (signer, from R-011 — spec-faithful, likely unintended by the spec). Gate (c) requires `now - LastSigned >= TTL floor`, but `LastSigned` is the *most recent* sign; a zone re-signed more often than the floor (default 24h) never satisfies it and its rollover sits in `pre_publish`/`signing` forever with only debug logs (`rollover.go:284-331`). Fix: track the first sign after `PhaseStarted` and gate on that.
5. **First-RRSIG-only selection can false-bogus healthy zones mid-rollover** (validator, from R-079/R-080). Both the DNSKEY check (`dnssec.go:291`) and the DS check (`validator.go:1052`) consider only the first RRSIG covering the type; a zone carrying two signatures (double-signature algorithm/KSK rollover) reads bogus whenever the non-matching one sorts first. RFC 4035 accepts an RRset if *any* RRSIG validates. Fix: iterate all covering RRSIGs.
6. **One NSEC3-hashing entry point escaped the RFC 9276 cap** (validator, R-088's residual gap — the reason it is PARTIAL). `verifyDSAbsence` (`validator.go:1151`, added by R-081) hashes with iterations taken from the parent's response, uncapped. Bounded (~one 65k-iteration hash per no-DS zone cut), far smaller than the original amplifier, but violates "cap at every entry point." Fix: call `nsec3IterationsOverCap` at the top of its NSEC3 branch.
7. **`ValidateAll` panic now kills the signer daemon** (from R-043). The dashboard validation compute moved from the panic-recovering HTTP handler goroutine into a bare goroutine (`web.go:51-59`) with no `recover` — a panic in live-DNS validation now takes down the whole daemon, against the codebase's own panic-isolation discipline (`checkAndSignZoneSafe`). Fix: `defer recover` in the compute goroutine.
8. **`runRegistrarPush` persists its URGENT warning outside the R-007 lock** (from R-004/R-032). `resolveRegistrar` loads state via unlocked `loadConfigAndState` (`registrar_cli.go:42`), so the `ErrRegistrarDSEmpty` warning's whole-map `state.Save()` uses a minutes-stale snapshot and can clobber concurrent writes — and the daemon's fresher-`LastSigned` merge then drops the warning itself. (The `maybeAutoPublishDS` call sites are correctly locked.) R-032's own spec said this Save must be under the lock. Fix: use `loadConfigStateLocked` for `registrar push`/`clear`.
9. **Syslog connection leak on SIGHUP** (from R-056). Re-running `setupLogging` with `--log-output syslog` dials a new syslog connection each reload and never closes the old `*syslog.Writer` (`main.go:266-278` tracks only `logFile`). One fd per SIGHUP — slow but unbounded under logrotate. Fix: track and close the previous syslog writer like the log file.
10. **`evalRRSIGCover` is order-dependent** (signer, from R-012). An answer holding an expired counted RRSIG *before* a valid one keeps `expired=true` (`validate.go:430-441`), so `checkRRSIGPresent` reports `fail`/"resolvers will SERVFAIL" while `soa_signed=true` — though resolvers accept an RRset if any RRSIG validates. One-line fix: clear `expired` when a valid signature is found (or gate the fail case on `expired && !valid`).
11. **`remove` silently succeeds on TOML header variants it cannot rewrite** (from R-008). `RemoveZoneFromConfigFile` exact-matches the `[zones."domain"]` header; a TOML-valid variant (inline comment after the header, whitespace, single quotes) misses, and `runRemove` swallows `errZoneNotInConfig` even though it already confirmed the domain *is* in the parsed config (`main.go:912`) — printing success while the zone remains and gets re-adopted after SIGHUP. Fix: when `inConfig` is true, treat rewriter not-found as an error.
12. **Post-sign verify gate can reject a previously-shippable zone with mixed-case duplicate owner spellings** (from R-001). `signRecordsWithKeys` groups case-insensitively but miekg `Verify`/`IsRRset` compares owner names case-sensitively, so an RRset spelled `www`/`WWW` now fails the gate (`sign.go:840`) though it signs and validates fine on the wire. Fail-closed and loud; rare input. Fix: canonicalize owner case before verification (or when grouping).
13. **Backup-exists skips check only the `.key` half** (from R-027/R-029). Both `backupExistingKeyFiles` (`keys.go:305-311`) and `backupKey` (`rollover.go:367-376`) treat a tag-named backup as complete when only its `.key` exists; a crash between `backupKey`'s two copies followed by a retry can lose the old `.private`'s only copy (fail-loud downstream, never silent; very narrow window). Fix: require the backup `.private` too before skipping.
14. **Daemon init branch not widened for keyless placeholders** (from R-033). `SignAll`'s condition was widened but `daemon.go:451` still tests only `zoneState == nil`, so a placeholder written by cron `sign` and merged into a running daemon is healed only by the next CLI `sign`, not by the daemon. Fix: mirror the widened condition.
