Sigillum 1.1 adds migration from existing DNSSEC signers and improves publication,
rollover, and validation reliability in both tools.

### Key-directory takeover and RSA signing

- `sigillum-signer import --keys-dir` inventories BIND-style key pairs, checks
  parent DS records and authoritative servers, and selects a compatible KSK and
  ZSK anchored at the parent's DS. It reports conflicting served chains as
  repairs and refuses an SOA serial rollback.
- `--dry-run` displays the inventory and plan without creating a state lock.
  Explicit key tags select a pair; `--offline` skips network checks. A KSK not
  named by the parent requires `--force`. Import does not update registrar DS
  records.
- RSASHA256 and RSASHA512 keys retain their algorithm through ordinary rollovers.
  Imported legacy 512-bit keys are supported; newly generated RSA keys are
  2048-bit. RSA private keys use BIND's multi-field format. SHA-1 RSA keys are
  listed but refused for signing.

See the [migration guide](https://github.com/ptudor/sigillum-dnssec/blob/v1.1.0/signer/README.md#migrating-from-another-signer)
for commands and takeover checks.

### Signing and validation fixes

- Publication hooks run after state is committed and apply only to their exact
  signed output and daemon generation. Hook dispatch is bounded, concurrent CLI
  state updates survive daemon saves, and registrar DS updates follow the
  rollover phase. Publication and parent-DS probes check every nameserver.
- Source content digests detect changes even when size and modification time
  stay the same. Input size and record limits preserve the last good output on
  oversized zones. Signature refresh follows actual expiry, and mixed-case
  NSEC3 zone signing is corrected.
- The validator selects responses using authenticated DNSSEC evidence, bounds
  authoritative query fanout, and releases resources when stream flushing fails.
  Reviewed, pinned root anchors are embedded for offline startup, with an atomic
  last-known-good cache kept separate from operator files.
- Integration URLs, redirects, outbound destinations, HTTP response sizes,
  timing settings, and typed environment values receive stricter validation.
  The validator updates `golang.org/x/net` to v0.59.0; dependency notices are
  refreshed and can now be maintained with `make update-notices`.

### Upgrading from 1.0.0

Back up signer keys, state, and configuration together before upgrading. Review
custom configuration: invalid timing values, malformed typed environment
variables, and invalid enabled integrations now fail explicitly. Signer
`signature_refresh` must cover at least two poll intervals; changing `data_dir`
requires a restart. A failed deployment hook makes CLI `resign` and `import`
return a nonzero status even when signing has committed successfully.

Packages preserve existing configuration and do not enable, start, or restart
services. Review the supplied configuration for the validator's optional
`root_anchors_cache_path`, then restart services explicitly after upgrading.

### Downloads and verification

Each archive contains both executables. Separate signer and validator packages
are available for Linux.

| Platform | Architectures | Files |
| --- | --- | --- |
| Linux | amd64, arm64 | `.tar.gz`, `.rpm`, `.deb` |
| FreeBSD | amd64, arm64 | `.tar.gz` with rc.d examples |
| macOS | amd64, arm64 | `.tar.gz` for local tools and development |

RPMs and DEBs are unsigned. Verify `checksums.txt` and the GitHub build
attestation before installation. Release checks include native race tests on
Linux amd64, Linux arm64, and macOS arm64; BIND RSA import and rollover
interoperability; all release cross-builds; Debian and Fedora package lifecycle
tests; vulnerability scans; and a full-history secret scan. FreeBSD artifacts
are cross-built, without native FreeBSD runtime tests in CI.
