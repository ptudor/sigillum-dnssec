Sigillum 1.2.0 fixes rollover propagation, DNSSEC validation, and package-upgrade
handling, and refreshes dependencies and release tooling.

### Signer fixes

- Change the parent's DS set only after the DNSKEY RRset carrying the new key
  has reached every authoritative server and expired from resolver caches.
  Algorithm rollovers also wait for the largest signed RRset TTL. Registrar
  failures are retried, and a KSK rollover does not complete before the required
  registrar update succeeds.
- Probe every nameserver by identity. On a single-stack host, skip a locally
  unreachable address family when that same nameserver answers through another
  address. Timeouts and refusals still block advancement and are reported in
  logs and status.
- Sign ordinary owner names beginning with an asterisk, such as `*foo` and `**`,
  with their full label count. Their escaped spelling in signed zone files
  preserves the same DNS wire name.

### Validator fixes

- Report descendants of an unauthenticated ancestor as indeterminate. Do not
  validate them using stale grandparent keys or unauthenticated parent keys,
  and do not report an unsigned child as insecure without an authenticated
  chain to its parent.
- Handle an NXDOMAIN response containing a signed CNAME or DNAME as an alias
  answer, validating the target's absence on its own hop. Correctly signed
  dangling aliases no longer become bogus solely because of that response form.

### Package upgrades

Create state directories on first installation only. Upgrades leave existing
ownership and permissions intact, preserve a `signed/` directory assigned to the
nameserver's group, and avoid following service-owned symlinks during privileged
ownership or permission changes.

### Dependencies and release tooling

- Update `github.com/prometheus/common` to v0.72.0 in both modules and refresh
  compiled dependency notices.
- Update the signer's `golang.org/x/net` to v0.59.0 and `golang.org/x/sys` to
  v0.48.0. Source builds of either module now require Go 1.26 or later.
- Continue building releases with Go 1.27.1. Update GoReleaser to v2.18.2,
  `govulncheck` to v1.8.0, and the SHA-pinned artifact-upload Action to v7.0.2.
- Retain dependency alerts and scheduled security checks while handling updates
  through repository maintenance instead of automatic pull requests.

### Upgrading

Back up configuration, keys, signed zones, and persistent state first. Packages
preserve configuration and do not enable, start, or restart services; restart
explicitly when ready to use the new executables.

Rollover state gains `ds_add_pushed_at`, and `phase_horizon` also records KSK and
algorithm propagation waits. Existing rollovers without a recorded horizon wait
until the daemon establishes one after upgrade. Preserve the state file and
allow those waits to complete; a slower rollover protects cached DNSKEY data.
No new configuration settings are required.

### Downloads and verification

| Platform | Architectures | Files |
| --- | --- | --- |
| Linux | amd64, arm64 | `.tar.gz`, signed `.rpm`, signed `.deb` |
| FreeBSD | amd64, arm64 | `.tar.gz` with deployment examples |
| macOS | amd64, arm64 | `.tar.gz` for local tools and development |

Archives contain both executables; Linux packages are separate for the signer
and validator. Verify `checksums.txt.sig`, the SHA-256 hashes, and the GitHub
build attestations. The release signing key remains
`8C4F 58EF B945 4902 267D 9B3E 426C 4AA2 1A40 0728`.

Release checks cover native race tests on Linux amd64, Linux arm64, and macOS
arm64, BIND RSA interoperability, every release cross-build, signed package
lifecycle tests in Debian and Fedora, vulnerability scans, and secret scans.
FreeBSD binaries are cross-compiled. These fixes do not imply that all remaining
review findings or deployment limitations have been resolved.
